## 2. 待补目标

### 2.1 API 路由集成测试（P0）

| 目标 | 关键断言 |
|---|---|
| `POST /api/chat` 限流分支 | 第 21 次请求返回 429 |
| `POST /api/chat` 末条消息非 user | 返回 400 |
| `POST /api/chat` 上游 4xx/5xx | 返回 502 且不透传上游正文 |
| `POST /api/chat` 上游无 body | 返回 502 |
| `GET /api/sessions` | 未登录 401；已登录只返回本人会话 |
| `GET /api/sessions/[id]/messages` | 他人会话返回 403；不存在返回 404；已登录本人按 `created_at` 升序 |
| `DELETE /api/sessions/[id]` | 他人会话 403；成功后消息与会话都被清理（验证调用顺序） |
| `GET /api/debug` | 下线或加鉴权后补对应断言 |

### 2.2 前端逻辑测试（P1）

| 目标 | 关键断言 |
|---|---|
| `useChatStream` 的 SSE 行解析 | 跨 chunk 截断的中文可正确拼接，不产生乱码或丢字 |
| 首 token 直出、后续节流 | 首个 token 立即进入 state；批量 token 合并为一次更新 |
| 取消路径 | `< 10` 字符移除气泡；`≥ 10` 字符追加 `[已取消生成]` |
| 超时路径 | 120s 触发后状态为 `error` 且追加 `[生成超时]` |
| 超长 / 重复 token | 触发 `AI_REPLY_TOO_LONG` 并追加对应标记 |
| 会话切换竞态 | 过期响应被丢弃，不覆盖新会话消息 |

实现思路：以 mock 的 `ReadableStream` 驱动 `fetch`，用 `@testing-library/react` 的 `renderHook`（已具备 `@testing-library/react` 与 `jsdom` 依赖）。

### 2.3 覆盖率门槛（P2）

- 先设全局行覆盖门槛（建议 60% 起步），再逐步上调；
- 对 `lib/validation.ts`、`lib/stream-processor.ts`、`lib/rate-limit.ts` 单独设更高门槛。

### 2.4 持续集成（P1）

- GitHub Actions：安装依赖 → `npm run test:ci` → `npm run build`；
- 任一步失败即阻断合并到 `main`；
- 与 Vercel 的自动部署配合：CI 通过后再让 Vercel 构建，避免坏提交直接上线。

## 3. 约束

- 测试必须 mock 外部依赖（Clerk、Supabase、上游模型），不得依赖真实网络与真实凭据；
- `lib/env.ts` 作为 mock 边界保留，避免测试导入 `lib/supabase.ts` 时因缺少环境变量而抛错；
- 不为提高覆盖率而写无断言价值的用例。
