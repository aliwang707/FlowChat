## 一、核心技术难点与突破

### 1. 前后端通信与 SSE 流式输出

- **初始困惑**：为什么 AI 的回答能一个字一个字蹦出来？前端如何接收这种数据流？
- **排查与突破**：
  - 学习 App Router 下 `app/api/chat/route.ts` 的约定：文件路径即 URL 路径。
  - 理解 SSE（Server-Sent Events）协议，通过 `ReadableStream` 和 `TextDecoderStream` 实现逐 token 返回。
  - **解决中文乱码**：TCP 分包会切断 UTF-8 多字节字符（中文占 3 字节）。通过引入 `buffer` 拼接被截断的 SSE 行，确保多字节字符完整后再解析。
- **验证方式**：
  - 在 Network 面板查看原始响应，确认乱码来自前端解析还是后端返回。
  - 用最小复现脚本模拟分包，验证 buffer 拼接逻辑。
- **收获**：分清了“字节流”与“字符流”的区别，能画出前端 Hook -> API Route -> 模型服务 -> UI 增量更新的完整数据流图。

### 2. 并发控制与状态管理

- **现象**：快速切换不同会话时，旧请求的 AI 回复会覆盖新会话的数据（竞态条件）。
- **解决方案**：
  - 在前端引入 `requestId` 或 `AbortController`，丢弃过期请求的响应。
  - 使用 `messagesRef` 保持数据最新，解决 React 异步任务中的函数闭包陷阱（Stale Closure）。
- **验证方式**：
  - 快速切换会话，观察 Network 面板中旧请求是否被取消。
  - 在回调中打印 `requestId`，确认过期响应被丢弃。
- **收获**：理解了 React 状态更新的竞态问题，学会了在异步任务中获取不被闭包捕获的实时状态。

### 3. 安全防护与工程化改造

当第一个能聊天的版本跑通后，我开始思考：如果上线，哪些地方会挂？于是进行了以下改造：

- **输入校验**：用 Zod 定义 Schema 替代手动 `if` 判断，使用 `safeParse` 避免异常直接抛出。实现编译时（TS）+ 运行时（Zod）的双重类型安全。
- **API 防护**：实现基于 `userId` 的内存滑动窗口限流（20 次/分钟），防止 API Key 被刷爆。注意：Serverless 多实例下内存限流不共享，生产环境可接入 Redis / Vercel KV。
- **超时联动**：使用 `AbortController` 设置 30 秒超时，并监听客户端 `request.signal` 的 `abort` 事件，级联取消上游 fetch，避免用户关闭页面时浪费 Token。
- **环境变量校验**：用 Zod 校验 `process.env`，启动时失败即构建失败，杜绝“本地能跑、部署就炸”的配置事故。
- **安全隔离**：严格区分 `NEXT_PUBLIC_` 变量和私密 Key，把 `SUPABASE_SERVICE_ROLE_KEY` 和 `SILICONFLOW_API_KEY` 只保留在服务端，避免 API Key 被前端打包泄露。
- **静态代码分析**：在 VS Code 中安装了 SonarLint 插件，实时扫描代码中的异味与潜在缺陷。重点关注“认知复杂度”“空 catch 块”“未处理的 Promise”等规则，并据此重构了 route.ts 中嵌套较深的错误处理逻辑，养成了写防御性代码的习惯。


### 4. 流式渲染体验优化与产品思维

- **性能优化**：引入 `lodash.throttle` 对高频 token 更新进行 50ms 节流，避免 React 渲染风暴；使用 `memo` 包裹重组件。注意最后一段 token 需要强制 flush，避免丢字。
- **渲染策略**：流式期间用纯文本渲染，避免未闭合的 Markdown 标签导致崩溃；流结束后再交给 `react-markdown` 完整渲染。
- **取消生成的产品决策**：区分“停止生成”与“回滚对话”。最终决策：保留用户消息，若 AI 已生成部分内容则保存并标记 `[用户已中断]`，过滤空消息避免污染上下文。
- **收获**：写 Demo 和写产品是两码事。技术实现之外，还需要从用户视角做数据一致性设计。

### 5. Vercel 部署与生产环境踩坑

- **构建失败**：本地 `npm run dev` 正常，但 `npm run build` 报 TypeScript 类型错误。养成 push 前本地跑一次 build 的习惯，提前拦截大部分线上构建失败。
- **线上 500**：通过 Vercel Runtime Logs 排查，发现环境变量作用域未勾选 `Production`。修改环境变量后，必须 `Redeploy` 才生效。
- **Supabase 连接超时**：理解 Serverless 环境下数据库连接数耗尽的风险，将直连切换为 Connection Pooling（端口 6543），问题明显缓解。
