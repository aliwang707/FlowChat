# 代码目录与文件职责

> 最后核对：2026-10-13
>
> 本文是逐目录、逐文件导航。分层与边界见[当前架构](当前架构.md)，请勿在此复制架构结论。

## 1. 顶层结构

| 路径 | 职责 |
|---|---|
| `app/` | App Router 路由、页面、全局样式、API Route Handler |
| `components/chat/` | 聊天 UI 组件（无数据获取，只接收 props） |
| `hooks/` | 客户端状态与副作用（唯一的状态所有权层） |
| `lib/` | 服务端领域服务与数据访问 |
| `tests/` | 路由层集成测试（Vitest） |
| `__test__/` | 校验逻辑单元测试（Vitest） |
| `docs/` | 本知识库 |
| `public/` | 静态资源与界面截图 |
| `proxy.ts` | 请求前置钩子（Next.js 16 用 `proxy.ts` 取代 `middleware.ts`） |
| `vitest.config.ts` / `vitest.setup.ts` | 测试运行配置与断言扩展 |

## 2. `app/`

| 文件 | 职责 |
|---|---|
| `layout.tsx` | 根布局：字体变量、`ClerkProvider`、页面 metadata |
| `page.tsx` | 唯一页面：组装登录门、侧边栏、消息列表、输入框；持有 `sidebarOpen` 与 `sessionRequestIdRef` |
| `globals.css` | Tailwind 入口与全局动画（如 `typing-bounce`） |
| `favicon.ico` | 站点图标 |
| `api/chat/route.ts` | 对话主链路：鉴权 → 限流 → 解析 → 校验 → 会话解析 → 存用户消息 → 调用模型 → 建立 SSE |
| `api/sessions/route.ts` | `GET` 当前用户会话列表（按 `updated_at` 倒序） |
| `api/sessions/[id]/route.ts` | `DELETE` 会话：先删消息再删会话，删除前校验归属 |
| `api/sessions/[id]/messages/route.ts` | `GET` 指定会话消息：先校验归属，再按 `created_at` 升序返回 |
| `api/debug/route.ts` | `GET` 环境自检，返回 Supabase URL 与 anon key 前缀/长度（待收口） |
| `.github/copilot-instructions.md` | 面向 AI 助手的「导师式」协作约定 |

## 3. `components/chat/`

| 文件 | 职责 |
|---|---|
| `ChatErrorBoundary.tsx` | 类组件错误边界，避免单点异常导致整树白屏 |
| `Sidebar.tsx` | 会话列表、新建会话、删除入口、`UserButton`；移动端为可滑出抽屉 |
| `MessageList.tsx` | 消息气泡渲染、复制按钮、空状态与加载态分发；`role="log"` + `aria-live` |
| `ChatInput.tsx` | 输入框与发送/取消按钮；处理 Enter 提交与中文输入法 `isComposing` |
| `StreamingMarkdown.tsx` | Markdown 渲染与自定义组件映射（代码块、表格族、段落、`pre`） |
| `CodeBlock.tsx` | 早期独立代码块组件，当前主链路由 `StreamingMarkdown` 内部实现承担（存在重复实现，见第 7 节） |
| `ui/EmptyState.tsx` | 空对话状态与快捷提问 |
| `ui/TypingDots.tsx` | 「思考中」三点动画 |
| `ui/Skeleton.tsx` | 会话列表加载骨架 |
| `ui/DeleteConfirmModal.tsx` | 删除确认弹窗，`role="alertdialog"` + `aria-modal` |

## 4. `hooks/`

| 文件 | 职责 |
|---|---|
| `useChatStream.ts` | 网络层流式读取与消息追加：构造请求、逐行解析 SSE、节流刷新、超时、取消、重置 |
| `useSessions.ts` | 会话列表、当前会话、历史消息加载、删除与 toast 反馈 |
| `useDarkMode.ts` | 深色模式状态、`<html>.dark` 挂载与 `localStorage` 持久化 |

## 5. `lib/`

| 文件 | 职责 |
|---|---|
| `supabase.ts` | 用 Zod 解析 `process.env`，创建 service role 的 Supabase 单例；关键变量缺失即抛错 |
| `env.ts` | 转发 `env` 与 `supabase`，便于测试 mock |
| `validation.ts` | `MessageSchema`（`strict`）与 `ChatRequestSchema` |
| `rate-limit.ts` | 按 key 的滑动窗口限流，含 5 分钟定时清理 |
| `ai-service.ts` | 唯一出网点：拼接 OpenAI 兼容请求体，返回上游 `Response` |
| `stream-processor.ts` | SSE 上游流解析器：跨 chunk 拼行、提取 `choices[0].delta.content`、触发首字节/完成/错误回调 |
| `sse-response.ts` | 构造对客户端的 SSE `Response`：包 `ReadableStream`、设置响应头、累积文本并在结束时落库 |
| `session-helpers.ts` | 数据层操作：存用户消息、存 AI 消息、按需生成会话标题 |

## 6. 测试

| 文件 | 覆盖 |
|---|---|
| `__test__/validation.test.ts` | `ChatRequestSchema` / `MessageSchema` 的合法与非法输入矩阵（含 `strict` 拒绝额外字段） |
| `tests/api/chat-route.test.ts` | `POST /api/chat` 的 401（未登录）与 400（非法载荷）分支；通过 mock 隔离 Clerk、限流与 Supabase |

## 7. 已识别的重复与死代码

| 位置 | 说明 | 处理建议 |
|---|---|---|
| `components/chat/CodeBlock.tsx` | 与 `StreamingMarkdown.tsx` 内部 `CodeBlock` 职责重叠，且 `memo`/`isStreaming` 参数在当前主链路未被使用 | 收敛为一个实现后再删除另一份 |
| `app/api/debug/route.ts` | 排障期产物，无鉴权 | 参见[验证状态与发布门禁](../quality/验证状态与发布门禁.md) |
| `lib/env.ts` | 纯转发层 | 保留即可，用于测试隔离 mock 边界 |

## 8. 配置类文件

| 文件 | 职责 |
|---|---|
| `next.config.ts` | 当前为空配置，未启用自定义实验特性 |
| `tsconfig.json` | `strict` + `noImplicitAny` + `strictNullChecks`，`@/*` 映射到项目根 |
| `tailwind.config.ts` | `content` 扫描规则；Tailwind v4 主题主要由 `globals.css` 的 `@import` 驱动 |
| `postcss.config.mjs` | 挂载 `@tailwindcss/postcss` |
| `vitest.config.ts` | `jsdom` 环境、`globals`、`@` 别名、`*.test.ts(x)` 收集范围 |
| `.env.example` | 环境变量模板（不含真实凭据） |
| `.gitignore` | 忽略依赖、构建产物、`.env*`（保留 `.env.example`） |
