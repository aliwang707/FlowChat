# 配置与请求防护架构

> 最后核对：2026-10-13
>
> 本文覆盖环境变量体系与请求入口的防护（校验、限流、长度与超时限制）。密钥可见性边界见[身份认证与访问控制架构](身份认证与访问控制架构.md)，决策见 [ADR 0003](../adr/0003-服务端密钥隔离与密钥边界.md)、[ADR 0004](../adr/0004-内存滑动窗口限流的适用边界.md)。

| 变量 | 必填 | 前端可见 | 用途 | 缺失行为 |
|---|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 是 | 是 | Supabase 项目地址 | 模块加载即抛错 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 是 | 是 | 匿名键（供公开场景） | 仅告警 |
| `SUPABASE_SERVICE_ROLE_KEY` | 是 | 否 | 服务端数据库凭据 | 模块加载即抛错 |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | 是 | 是 | Clerk 前端公钥 | 不由本仓库校验，登录直接失败 |
| `CLERK_SECRET_KEY` | 是 | 否 | Clerk 服务端密钥 | 同上 |

| `AI_FIRST_BYTE_TIMEOUT_MS` | `app/api/chat/route.ts` 的 `FIRST_BYTE_TIMEOUT` | 未出现在 `envSchema` 与 `.env.example`，只能直接注入 `process.env`，运维不可见 |

## 2. 校验策略

`lib/supabase.ts` 用 Zod 定义 `envSchema` 并 `safeParse(process.env)`：

- **校验失败只告警**：打印 `环境变量校验未通过，构建将继续；运行期需补齐配置后再访问对应功能。` 并逐条列出问题，然后回退到手工兜底对象。这与 README 早期「缺失即构建失败」的描述不一致，以代码为准。
- **关键变量缺失即抛错**：`NEXT_PUBLIC_SUPABASE_URL` 或 `SUPABASE_SERVICE_ROLE_KEY` 缺失时，模块加载阶段直接 `throw`，避免静默连到假地址。
- **类型强制**：数值类变量使用 `z.coerce.number()`，默认值在 Schema 内声明，减少散落的 `Number(...)`。

## 3. 请求入口防护

`POST /api/chat` 按固定顺序执行防护，任何一层失败都不进入下一层：

| 顺序 | 防护 | 失败响应 |
|---|---|---|
| 1 | 登录校验 | 401 |
| 2 | 限流 | 429 |
| 3 | JSON 解析 | 400 `JSON请求格式错误` |
| 4 | Zod Schema 校验（`strict`） | 400，逐条拼接 `path:message` |
| 5 | 末条消息必须为 `user` | 400 `最后一条消息必须来自用户` |
| 6 | 上下文裁剪 | 静默，仅取最后 20 条 |

### 长度与资源上限

| 限制 | 值 | 位置 |
|---|---|---|
| 单条消息长度 | 1 ~ 10000 字符 | `MessageSchema` |
| 上下文条数 | 1 ~ 20 条 | `ChatRequestSchema` 与路由内 `slice(-20)` |
| 上游 `max_tokens` | `min(AI_MAX_TOKENS \|\| 1024, 1024)` | `app/api/chat/route.ts` |
| 单次回复前端上限 | 15000 字符 | `hooks/useChatStream.ts` |
| 连续重复 token | 超过 10 次即中断 | `hooks/useChatStream.ts` |

`AI_MAX_TOKENS` 的 Schema 默认是 2048，但路由将其硬夹在 1024，属于隐性上限，调整模型输出长度时必须改这两处。

## 4. 限流实现

- **算法**：滑动窗口（简化实现，记录窗口起始时间与计数）。
- **键**：Clerk `userId`。
- **参数**：窗口 60 000 ms，上限 20 次。
- **清理**：`setInterval` 每 5 分钟清理过期记录，避免单进程内存持续增长。
- **适用范围**：仅覆盖 `POST /api/chat`；会话读/删接口未限流。
- **失效条件**：Serverless 多实例部署下 `Map` 不共享，实际放行量约为「实例数 × 20」，仅适合作为演示与本地保护。生产替换方案见 [ADR 0004](../adr/0004-内存滑动窗口限流的适用边界.md)。

## 5. 已知缺口

| 缺口 | 影响 | 追踪 |
|---|---|---|
| 多数变量缺失只告警 | 配置错误推迟到运行期才暴露 | 待收口 |
| `AI_FIRST_BYTE_TIMEOUT_MS` 未登记 | 运维无法发现与调整 | 发布门禁 |
| `AI_MAX_TOKENS` 双重默认值 | 2048 与 1024 不一致，误改易出错 | 待统一 |
| 限流不跨实例、不覆盖读接口 | 生产防护不成立 | [限流与可观测性收口](../roadmap/限流与可观测性收口.md) |
| 无请求体大小限制 | 超大 JSON 会先被解析再校验 | 可在 proxy 层加早退 |
| 无并发请求数限制 | 同一用户可并发多路流式，占用上游配额 | 未排期 |
