# 测试目录组织规范

> 最后核对：2026-10-13

## 1. 目录职责

| 目录 | 放什么 | 命名 |
|---|---|---|
| `__test__/` | 纯逻辑单元测试（Schema、纯函数、解析器） | `<模块名>.test.ts` |
| `tests/api/` | Route Handler 集成测试（含 mock 边界） | `<路由名>.test.ts` |
| `tests/`（未来） | 前端 hook 与组件测试 | `hooks/<hook>.test.ts`、`components/<组件>.test.tsx` |

当前 `tests/` 下只有 `api/` 子目录；新增前端测试时按上表扩展，不要把 hook 测试塞进 `__test__/`。

## 2. 运行配置

- `vitest.config.ts`：`jsdom` 环境、`globals: true`、`setupFiles: ./vitest.setup.ts`、收集 `**/*.test.ts(x)`、别名 `@` → 项目根。
- `vitest.setup.ts`：引入 `@testing-library/jest-dom` 断言扩展。
- 命令：`npm run test`（watch）、`npm run test:ci`（单次，供 CI 使用）。

## 3. 编写约定

1. **测试名用中文行为描述**：`it('messages 不能超过 20 条（防上下文溢出）')` 优于 `it('should fail')`。
2. **用 `describe` 按维度分组**：合法输入 / 非法输入的每个字段各成一组。
3. **断言具体值**：校验逻辑断言 `result.success`，接口测试断言状态码 **和** 关键响应字段，不只断言状态码。
4. **边界必须有对应用例**：每个上下限（1 与 0、20 与 21、10000 与 10001）都要成对出现。
5. **必须 mock 外部依赖**：Clerk（`@clerk/nextjs/server`）、限流（`@/lib/rate-limit`）、Supabase（`@/lib/supabase`）、上游模型（`global.fetch`）。
6. **不用真实网络与真实凭据**：任何需要真实 Key 的用例都不应进入仓库。
7. **每个用例独立**：`beforeEach` 中 `vi.clearAllMocks()`，禁止用例间共享可变状态。

## 4. mock 边界约定

`lib/env.ts` 是专门为测试保留的转发层，用于在不加载 `lib/supabase.ts` 的情况下替换 `env`：

```ts
// 参考 tests/api/chat-route.test.ts 的既有写法
vi.mock('@/lib/env', () => ({ env: { AI_MODEL: '...', AI_MAX_TOKENS: 1024 } }));
```

`lib/supabase.ts` 在模块加载时会因缺少关键环境变量抛错，测试中必须通过 `importOriginal` 保留其余导出并覆盖 `env`、`supabase`。

## 5. 提交前检查

- [ ] `npm run test:ci` 全绿
- [ ] 新增行为同时新增用例，或明确在[验证状态与发布门禁](验证状态与发布门禁.md)第 1.2 节登记为未覆盖
- [ ] 无用例依赖真实网络、真实凭据或执行顺序
