# 成熟软件完整性审计

> 最后核对：2026-10-13
>
> 本文对照主流 AI 聊天产品（ChatGPT、Claude、Kimi、通义千问）的形态，审计 FlowChat 已具备的能力与缺口。只描述差距本身，不把外部产品行为定义成本项目需求；是否补齐由[产品全量功能清单](产品全量功能清单.md)决定。

## 1. 审计结论

FlowChat 在「单用户、单模型、以对话为核心」的主路径上已经闭环：登录 → 建会话 → 流式对话 → 落库 → 回看历史 → 删除会话，且具备请求校验、限流、超时取消、越权防护等生产向的处理。

缺口集中在三类：

1. **对话能力的深度**：无检索增强、无工具调用、无多模态、无结构化输出。
2. **对话体验的完整性**：无重新生成、无消息编辑、无分页、无断线续传、无反馈闭环。
3. **工程可交付性**：限流不跨实例、自检接口未下线、API 集成测试缺失、无监控告警。

## 2. 已具备的能力

| 维度 | 现状 |
|---|---|
| 实时性 | SSE 逐 token 输出，首字节超时保护，可中断 |
| 持久化 | 会话与消息全部落 Supabase，刷新不丢 |
| 访问控制 | 服务端逐请求鉴权 + 归属校验，用户间完全隔离 |
| 输入安全 | 双层类型校验、角色防伪造、上下文与长度双上限、请求限流 |
| 展示 | Markdown / 代码高亮 / 表格降级 / 深色模式 / 响应式 |
| 可用性 | 错误边界、Toast 反馈、骨架屏、空状态引导 |
| 交付 | GitHub → Vercel 自动部署，自定义域名 |

## 3. 能力缺口

### 3.1 对话深度

| 能力 | 现状 | 影响 |
|---|---|---|
| 检索增强（RAG） | 无 | 无法基于用户文档问答 |
| Function Calling / Tool Use | 无 | 无法查天气、算数、访问外部系统 |
| 结构化输出（JSON Schema） | 无 | 无法稳定地被下游程序消费 |
| 多模态（图片/语音输入） | 无 | 只能纯文本 |
| 模型切换与参数自定义 | 仅环境变量级 | 用户无法按需选择模型与温度 |
| 系统提示词可配置 | 硬编码中文助手 | 无法做垂直领域助手 |

### 3.2 对话体验

| 能力 | 现状 | 影响 |
|---|---|---|
| 重新生成上一条回复 | 无 | 不满意只能重发 |
| 编辑已发消息 | 无 | 输错只能重来 |
| 历史消息分页 / 虚拟滚动 | 无 | 长会话一次性全量拉取 |
| 流式断线续传 | 无 | 网络抖动会丢本次输出 |
| 点赞 / 点踩 / 反馈 | 无 | 无法收集质量信号 |
| 会话搜索 | 无 | 会话多了只能靠标题翻 |
| 导出 / 分享会话 | 无 | 无法带走或外发内容 |
| 消息引用与多轮追问定位 | 无 | 长对话难以定位上下文 |
| 未发送草稿保存 | 无 | 刷新丢草稿 |
| 请求失败自动重试 | 无 | 失败需手动重发 |

### 3.3 工程可交付性

| 能力 | 现状 | 影响 |
|---|---|---|
| 限流跨实例共享 | 内存 Map，仅单实例有效 | 多实例部署下限流形同虚设 |
| `/api/debug` 下线 | 无鉴权对外暴露 | 泄露 Supabase 地址与 key 前缀 |
| API 路由集成测试 | 仅 3 个用例 | 主链路回归依赖手工 |
| 前端 hook / 组件测试 | 无 | 竞态、节流、中断逻辑无自动化保护 |
| 覆盖率门槛 | 未设置 | 覆盖率不可度量 |
| 结构化日志与错误上报 | 仅 `console.error` | 线上问题缺少可检索证据 |
| 数据库迁移脚本入库 | 无，建表 SQL 只在部署文档口述 | 环境重建不可复现 |
| 无障碍与键盘导航完整覆盖 | 部分 | 仅输入框与主要按钮覆盖 |
| 国际化 | 无，全中文硬编码 | 无法面向非中文用户 |

## 4. 补齐优先级建议

> 优先级是建议，不代表已排期；实际排期以 `roadmap/` 为准。

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 下线或给 `/api/debug` 加鉴权；把建表 SQL 入库 | 安全与可复现性风险，成本极低 |
| P0 | 补 API 路由集成测试（含越权、限流、中断路径） | 主链路目前缺自动化 |
| P1 | 限流换共享存储（Redis / Vercel KV） | 上线多实例后立即失效 |
| P1 | 重新生成与消息编辑 | 对话体验最影响留存的两项 |
| P1 | 结构化日志与错误上报 | 没有证据就无法稳定运维 |
| P2 | RAG 与 Tool Use | 从「能聊」升级到「能干活」 |
| P2 | 会话搜索、导出、反馈闭环 | 会话数量上去后的必要能力 |
| P3 | 多模态、国际化、模型切换 | 面向更大用户群时再投入 |
