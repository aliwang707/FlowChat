# 部署与运行环境

> 最后核对：2026-10-13
>
> 本文只记录 Vercel 运行环境的长期事实。部署历程的完整叙事见[Vercel 部署全记录](../../deployment-vercel.md)。

## 1. 交付形态

| 项 | 值 |
|---|---|
| 托管平台 | Vercel |
| 触发方式 | `main` 分支推送触发自动构建与发布 |
| 运行形态 | Serverless Function（Route Handler 按需执行） |
| 域名 | 默认 `*.vercel.app`；当前绑定自定义域名 `flowchat.boleit.cn` |
| 仓库 | `github.com/aliwang707/FlowChat` |
| 演示地址 | `https://flowchat.boleit.cn/` |

本地开发使用 `npm run dev`（`http://localhost:3000`）；`npm run build` 是推送前的强制自检，用于拦截 TypeScript 与构建期错误。

## 2. 环境变量

### 2.1 必填

| 变量 | 前端可见 | 说明 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 是 | Supabase 项目地址 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 是 | 匿名键（当前前端未直接使用 Supabase SDK） |
| `SUPABASE_SERVICE_ROLE_KEY` | 否 | 服务端数据库凭据，绕过 RLS |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | 是 | Clerk 前端公钥 |
| `CLERK_SECRET_KEY` | 否 | Clerk 服务端密钥，必须与 publishable key 同环境 |
| `SILICONFLOW_API_KEY` | 否 | 上游模型密钥 |
| `SILICONFLOW_BASE_URL` | 否 | 上游接口地址（见第 4 节区域问题） |

### 2.2 可选

| 变量 | 默认 | 说明 |
|---|---|---|
| `NEXT_PUBLIC_APP_URL` | 无 | 应用访问地址 |
| `AI_MODEL` | `Qwen/Qwen2.5-7B-Instruct` | 默认模型名 |
| `AI_MAX_TOKENS` | 2048（运行时夹到 1024） | 最大输出长度 |
| `AI_TEMPERATURE` | 0.7 | 采样温度 |
| `AI_TOP_P` | 0.9 | top-p |
| `AI_FIRST_BYTE_TIMEOUT_MS` | 60000 | 首字节超时；**未登记进 `.env.example`** |

### 2.3 配置纪律

- 作用域（Production / Preview / Development）必须与目标环境匹配，只勾 `Preview` 会导致线上读不到变量；
- **修改环境变量后必须 Redeploy**：变量在构建时注入，刷新页面不生效；
- 服务端密钥绝不加 `NEXT_PUBLIC_` 前缀（见 [ADR 0003](../../adr/0003-服务端密钥隔离与密钥边界.md)）。

## 3. 函数时长与流式约束

| 约束 | 值 | 位置 |
|---|---|---|
| 函数最大执行时长 | 60s | `app/api/chat/route.ts` 的 `export const maxDuration = 60` |
| 首字节超时 | 60s（可配） | 同文件 `FIRST_BYTE_TIMEOUT` |
| 客户端整体超时 | 120s | `hooks/useChatStream.ts` |

SSE 在 Vercel 上必须显式对抗边缘代理缓冲，否则会出现「等很久一次性蹦出」：

- `Content-Type: text/event-stream; charset=utf-8`
- `Cache-Control: no-cache, no-transform`
- `X-Accel-Buffering: no`
- `Content-Encoding: identity`（同时要求上游 `Accept-Encoding: identity`）

`maxDuration` 的实际可用范围以当前 Vercel 计划为准，超计划会被平台截断。

## 4. 区域与网络

Vercel 默认部署在海外区域，访问国内端点 `api.siliconflow.cn` 可能超时。当前处理方式是把 `SILICONFLOW_BASE_URL` 切到国际节点 `https://api.siliconflow.com`。

备选方案：更换为其他 OpenAI 兼容服务（DeepSeek、智谱、Moonshot），或增加超时重试。切换供应商只需改环境变量与 `AI_MODEL`，不影响前端（见 [ADR 0002](../../adr/0002-SSE流式响应协议.md)）。

## 5. 数据与连接

| 项 | 事实 |
|---|---|
| 数据库 | Supabase Postgres，服务端用 service role key 访问 |
| 连接方式 | 直连在 Serverless 下易耗尽连接数，已切换为 Connection Pooling（端口 6543） |
| RLS | 未启用（`user_id` 与 `auth.uid()` 类型不匹配），鉴权由应用层承担 |
| 建表 SQL | **未入库**，只能在部署时手工执行（见发布门禁 G-02） |

## 6. 部署后验证

发布后必须确认（完整清单见[Vercel 部署全记录](../../deployment-vercel.md)第 4 节）：

- 页面可加载，无白屏与 500；
- 未登录调用 `/api/chat` 返回 401，登录后能收到逐字流式回复；
- 环境变量注入正确，无认证错误；
- Vercel Runtime Logs 无异常；
- 断网或上游故障时前端展示友好提示。

## 7. 已知环境缺口

| 缺口 | 影响 |
|---|---|
| 无 CI 前置，Vercel 直接构建 | 坏提交会先上线再被发现 |
| 无 Preview 环境的独立数据隔离 | Preview 可能与生产共享同一 Supabase 项目 |
| 无自动回滚策略 | 故障时依赖手动 Redeploy 上一版本 |
| 无额度与错误率告警 | 额度耗尽只能靠用户反馈发现 |
