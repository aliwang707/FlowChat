# FlowChat 工程知识库

> 状态：AI 与开发者的文档入口
>
> 最后核对：2026-10-13

`docs/` 只保存能够指导当前设计、开发、验证和交付的知识：当前事实、长期合同、产品需求、可复用的决策与踩坑经验，以及尚未完成的路线。逐次提交记录由 Git 追溯，不在知识库中归档。

学习过程与 AI 协作复盘属于个人叙事，保留在 [`learning-log.md`](learning-log.md) 与 [`ai-collaboration.md`](ai-collaboration.md)，不作为技术事实来源。

## 1. 最小必读上下文

处理任何功能或架构任务前，只需先读三份文档：

1. [产品全量功能清单](product/产品全量功能清单.md)：唯一的产品范围、稳定 ID 和状态来源；
2. [当前架构](architecture/当前架构.md)：当前分层、状态所有权、模块边界与已知缺口；需要逐目录、逐文件导航时查阅[代码目录与文件职责](architecture/代码目录与文件职责.md)；
3. [验证状态与发布门禁](quality/验证状态与发布门禁.md)：当前自动化证据、未验证能力和发布前必须收口的事项。

只有任务涉及特定领域时，再按下面的路由读取专题文档。不要默认把全部 `docs/` 加入上下文。

## 2. 冲突处理顺序

当两份文档或文档与代码不一致时，按以下顺序取信：

1. 可执行代码、自动化测试与线上（Vercel Production）实际行为；
2. [产品全量功能清单](product/产品全量功能清单.md)中的范围与状态；
3. [当前架构](architecture/当前架构.md)中的技术事实；
4. 已接受 ADR；
5. 尚未完成的路线图；
6. 带环境与方法的质量/平台证据；
7. [`learning-log.md`](learning-log.md)、[`ai-collaboration.md`](ai-collaboration.md)等主观复盘。

目标方案不能证明当前实现；本地 `npm run dev` 不能证明线上行为；外部分析也不能替代本仓库的代码、契约与验证证据。

## 7. 维护要求

- 新需求先进入产品清单并分配稳定 ID；占位入口不等于已实现。
- 当前实现变化同步更新[当前架构](architecture/当前架构.md)；重大不可逆取舍新增或取代 ADR。
- 自动化和线上证据只在 `quality/`、`platform/` 维护，其他文档使用链接引用。
- 同一事实只保留一个权威来源，不复制功能总数、测试数量或阶段状态。
- 已完成路线不保留阶段工作项；长期合同迁入架构，可复用踩坑写成「根因 + 预防门禁」。
- 架构文档优先描述语义合同与边界，不整段复制实现代码；协议载荷与可复现命令按维护规范例外处理。
- 文档与代码不一致时，先改文档再改结论；不允许让文档停留在已知错误状态。
- 完整规则见[知识库维护规范](知识库维护规范.md)。
